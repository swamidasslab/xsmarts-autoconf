Contribute

Every row here comes from a small executable test in xsmarts-autoconf. Pull requests are welcome, especially from people who know a library's corners.

Add a test or behavior

  1. Add a JSON rule in src/xsmarts_autoconf/data/rules/<area>/: the smallest cases that separate the behaviors, one value per behavior, and provenance.
  2. If a value is a bug or silent failure, list it in data/site/severity.json so it shows red.
  3. Run xsmarts-autoconf update and commit the refreshed configs for the library versions you have.

Add a library (harness)

  1. Subclass Adapter in adapters.py: implement version, parse, match, apply and sanitize, whichever the library supports. Imports stay optional.
  2. Register it in ADAPTERS and run xsmarts-autoconf update <name>.
  3. Commit data/configs/<name>/<version>.json; it appears here on merge.

Add a library version

  1. Install another version of a covered library.
  2. Run xsmarts-autoconf check, then update.
  3. Send the new config file; it becomes a selectable version above.

Contributing guide Report a behavior

Colors. red: an error, silent failure or corrupted product. orange: a policy or semantic difference that differs from what most tools do. green: the behavior most tested libraries share. gray: no known value matched. A row takes its worst cell. Click a row for its test cases and observed outputs.
